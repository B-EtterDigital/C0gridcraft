# C0sheet: GridCraft as a C0VIBE guest page

This page builds the existing `apps/gridcraft-web` binary with the opt-in `page-control`
feature. The workbook engine, importers, ribbon and rendering remain GridCraft's. No alternate
editor, maintained JavaScript bundle or external assets are added. The body and canvas are
transparent until the app paints, leaving the host free to draw its loading state.

Build from this directory on the executor:

```sh
smoac-slot run heavy 2 3600 -- env CARGO_BUILD_JOBS=2 NO_COLOR=true trunk build --release
```

Trunk writes `../../dist/c0host`, hashes artifacts and uses relative public URL `./`. Serve that
directory over HTTP(S) and retain relative paths when relocating it. The emitted JavaScript is
generated by Trunk from Rust. The ordinary web build still writes `dist/web` and exposes no page
function unless the feature is selected. The existing `?host=parent` postMessage implementation
is untouched; its author/open/save notifications remain a separate transport.

## Page function and envelopes

The host calls `window.__c0hostRequest(jsonText)`, an alias for `window.__gridcraftControl`.
It has exactly the WordCraft page's readiness semantics: the alias is a getter, undefined until
the Rust bridge installs the underlying function. Wait for it to become a function before calling.
Input is a JSON **string**, never an object. Output is a string or a Promise of a string; this
implementation returns a Promise. Await it, then decode JSON.

Request: `{"method":"c0.inspect","params":{}}`. Missing or null params default to `{}`;
other non-object params are errors. Optional request ids are ignored; the Promise pairs the reply.
Every reply is either `{"ok":true,"result":...}` or `{"ok":false,"error":"..."}`.
Unknown methods and malformed requests use the same error envelope.

Ordinary requests are capped at 1 MiB. The `c0.*` family accepts up to 100 MiB of JSON, leaving
room for a 72 MiB file encoded as standard padded base64 plus its envelope. File basenames are
limited to 255 bytes; paths, NUL, `.` and `..` are refused. These limits are defined once in
`c0_host` and shared by the page and file paths. A file's compressed bytes being bounded does
not replace the underlying importer's own workbook limits.

The page additionally bounds `ui.click`/`ui.cell.click` to 256 clicks and `ui.drag` to 32 steps.
Larger counts return an error before reaching the upstream event allocator.

## When a request is answered

The bridge lends a pass from the **same WebRunner** using its event-listener mechanism, following
WordCraft and PhotoCraft. Inside the call it drains `SheetApp.control_rx` and lays out egui without
painting. Ordinary immediate replies therefore need no presented frame, including when a guest
is hidden. A changed request asks for a repaint after the pass. `c0.inspect` and `c0.documentBytes`
only read and do not themselves request a repaint. Upstream ordinary control methods retain their
own repaint behaviour, even when the bridge classifies them as reads.

Synthetic input acknowledges queueing. The bridge runs up to 40 extra inline passes to play it;
longer queues retain upstream semantics. Delayed work gets additional passes while egui asks for
repaint, at most once per 16 ms. `ui.screenshot` still needs presented pixels and has the upstream
timeout. Before the runner can lend a pass, the bridge wakes it and waits. Callers own transport
timeouts; the bridge does not introduce a deadline. Native unpainted-pass tests verify the queue;
native feature tests, the wasm check and the Trunk build cover browser compilation.

## Host methods

| Method | Params | Result |
|---|---|---|
| `c0.inspect` | `{}` | Workbook and host state described below |
| `c0.goTo` | `{sheet?: name or zero-based index, ref?: "D800:F802"}` | Existing activation result `{sheet,name}` or selection result `{selection,active}` |
| `c0.documentBytes` | `{format?: "xlsx", "csv" or "pdf"}`; default xlsx; pdf also takes `sheets?` ("active" or "all"), `range?`, `fitToPage?` | `{name,format,bytes,revision}` (pdf adds `pages`); `bytes` is standard padded base64 |
| `c0.openFile` | `{name,bytes}` | Existing `file.open` result `{index,title,sheets,warnings}` or `{pending:true}` |
| `c0.newDocument` | `{template?: "blank"}`; empty string also means blank | Existing `file.new` result `{index,title}` or `{pending:true}` |
| `c0.cancelFileDialog` | `{}` | `{cancelled: boolean}` |
| `c0.set` | `{themeTokens?,panels?}` | `{applied: string[],unknown: string[],invalid: string[]}` |

`inspect` returns:

```json
{
  "title": "Book1", "dirty": false, "revision": 1,
  "sheets": [{"name":"Sheet1","active":true,"hidden":false}],
  "activeSheet": 0, "activeCell": "A1", "selection": "A1",
  "names": [{"name":"Rate","ref":"=Sheet1!$A$2"}],
  "tables": [{"name":"Sales","sheet":"Sheet1","ref":"A1:B3"}],
  "canUndo": false, "canRedo": false,
  "panes": {"formulaBar":true,"headings":true,"gridlines":true,"statusBar":true,
            "toolbar":true,"toolbar_double":false,"toolbar_floating":false,"right_dock_collapsed":false},
  "ribbonCollapsed": false, "theme": "light"
}
```

Names and tables above are illustrative; a blank workbook returns empty arrays. `activeSheet` is
a zero-based index, table `sheet` is its sheet name, and both hidden visibility modes report
`hidden:true`. `revision` is the active `DocState.revision`; it resets with a new document and
is not a global revision sequence. `theme` is the selected preference: `light`, `dark` or `system`.
There must be an active workbook for inspect or byte export.

`goTo` accepts A1 ranges (including `$` absolute markers, whole rows/columns), using the explicit
`sheet` separately. It refuses hidden or nonexistent sheets and validates before changing the
selection. Omitting `ref` activates the sheet and keeps its selection memory; omitting both leaves
the current selection. It commits an in-progress cell edit through the normal validation path,
selects via commands, exits Backstage and asks the grid to reveal the active cell during layout.
If draft validation fails, navigation and replacement return the validation error in the reply,
retain the draft and leave the workbook in place, without opening a validation message box.

`documentBytes` uses the same encoder and naming as `file.saveBytes`. CSV exports the active
sheet. PDF is the engine's own writer (`file.exportPdf`, the one behind Print) run on a private
session holding a copy of the committed workbook, with no path, so the browser's missing file
system is not involved and the open document's journal, history and revision stay untouched.
`sheets`, `range` and `fitToPage` pass to the engine and its errors come back in the reply. It reads the committed workbook, leaves an in-progress edit alone, and changes neither
dirty/saved state, revision, undo/redo nor scroll state. It never invokes a picker or download.

`openFile` sends bytes through GridCraft's importer and `file.open`. Every existing importer and
content-sniffing path remains available: XLSX/XLSM/template variants, XLS, XLSB, ODS, CSV, TSV/TXT,
and GridCraft JSON. Invalid or encrypted imports are rejected before discarding any workbook;
this method has no password dialog or password parameter. No vendor fixtures or assets are added.
Importer warnings remain in the result and the existing notice strip, without a message box.

GridCraft normally opens multiple workbooks. Host Open/New replace **only the active workbook**,
retaining any other open workbooks. Replacement first commits the current edit, then calls the
existing `file.close`. A clean workbook closes immediately. A dirty workbook opens GridCraft's
existing Save Changes prompt and returns `{pending:true}`. This is acceptance of a pending
operation, not confirmation that replacement has occurred. Cancel preserves the old workbook;
Don't Save, or a successful Save followed by close, completes the operation in the next logic
pass. Poll `c0.inspect` to observe the resulting document. A second replacement while one is
pending is refused. Dismiss unrelated dialogs before replacing a workbook.
An unexpected failure while finishing a pending replacement is shown in the existing warning
notice strip; the host adds no error dialog.

The host adds no save/discard dialog. In the ordinary standalone browser services, Save downloads
bytes asynchronously and does not itself mark the workbook saved or close it. If that upstream
path does not complete Close, the host replacement is cancelled and the dirty workbook is kept.
The existing parent transport separately marks a handoff as saved after layout; it does not force
this pending replacement to close. Hosts can export bytes themselves and use the existing prompt's
Don't Save action after successful persistence.

The bounded page picker keeps GridCraft's normal inbox, importer, warning and password-dialog
behaviour. Only one chooser request is current. `cancelFileDialog` retires that request; a native
browser chooser may remain visible, but a late answer is ignored. It does not answer Save Changes,
discard an edit, or cancel a browser download/save ticket. A valid Open/New request supersedes the
picker after validation. Cancellation with no current picker returns `{cancelled:false}`.

## Chrome settings

All panel values are booleans. Known non-booleans go to `invalid`; unrecognised keys go to
`unknown`. Each accepted key is reported as `panels.<key>`. Repeated values are idempotent.

| Key | Effect |
|---|---|
| `title_bar` | Existing `Chrome.title_bar` (default true) |
| `file_tab` | Existing `Chrome.file_tab`; false closes Backstage (default true) |
| `community_links` | New default-true Chrome switch; false removes the About promotion, website and Discord links, retaining GridCraft, contributor tabs and licence |
| `agent_control` | New default-true Chrome switch; false removes Automate's Agent Control button/KeyTip and refuses `ui.dialog {name:"agents"}`, including command aliases and native menu entry |
| `ribbon_collapsed` | Existing collapse command, executed only if the requested value differs |
| `formula_bar` | Existing `view.formulaBar` application preference |
| `headings` | Existing `view.headings` workbook setting |
| `gridlines` | Existing `view.gridlines` workbook setting |
| `status_bar` | Existing `UiState.status_bar` |
| `toolbar` | The ribbon's command card (default true); false collapses the ribbon to its tab row. Independent of `ribbon_collapsed`, which stays the user's own switch |
| `toolbar_double` | Compact ribbon: every big button becomes an icon button (accessible name and tooltip kept), so the ribbon is narrower; its height is unchanged because this ribbon's groups stack up to three rows |
| `toolbar_floating` | The whole ribbon becomes a movable palette over the canvas instead of a docked panel; the canvas takes the docked height back |
| `right_dock_collapsed` | The right dock (task panes and the PivotTable fields pane) folds to a narrow icon strip; each pane's icon opens it |

### Tool modes: the ribbon

GridCraft has a ribbon, not a tool strip, so the PhotoCraft keys map onto it. The combinations:

| `toolbar` | `toolbar_double` | `toolbar_floating` | What is drawn |
|---|---|---|---|
| true | false | false | Upstream's ribbon, docked and full (the default) |
| true | true | false | Docked, compact: icon buttons in the same card height |
| false | any | false | Docked, collapsed to the tab row |
| true | false | true | A floating full ribbon |
| true | true | true | A floating compact ribbon |
| false | any | true | A floating tab row |

The floating ribbon is an egui area above the canvas with a grip (accessible name "Move Toolbar")
to drag it by; it stays inside the canvas area. Its position is not part of `c0.set`. The right dock:
the unfolded dock is upstream's, and with no pane open it draws nothing, as before. Folded, it is a
34 pt strip with an icon for Comments, Watch Window, Selection and Format Chart Area (plus PivotTable
Fields while a pivot cell is active). An icon opens its pane and unfolds the dock to the width it had;
the chevron unfolds it as it was; an unfolded pane's header has a button that folds it again. The
change is immediate and only the canvas width changes.

## `ui.render`

`ui.render {sheet?, scale?}` (a control method, not a `c0.` one) returns `{base64,width,height,sheet,scale}`:
a PNG of the visible grid, the area the grid occupies on screen, without the ribbon, panes or window.
`sheet` is a name or zero-based index (default: the active sheet, hidden sheets are refused);
`scale` is 0.25 to 4 (default 1). It is drawn by the app's own grid painters on a private egui
context and rasterised on the CPU, so it needs no presented frame, works for a hidden guest and
changes nothing in the open app. Before the guest was ever laid out it uses 960 x 600 points. Right-to-left
sheets are not mirrored and Page Layout view is drawn as the normal grid.

Chrome describes the host and is not persisted as user preferences. Workbook view commands retain
their upstream dirty/history semantics. Other visibility state retains its existing persistence.

## Runtime theme tokens

`themeTokens` replaces the context-local override set; `{}` or null clears it. Absent leaves it
unchanged. Values are `#rrggbb` or `#rrggbbaa`, case insensitive; alpha is unpremultiplied input.
Valid keys apply even alongside unknown or invalid siblings, reported as `themeTokens.<key>`.
Overrides survive light/dark/system changes and reapplication of upstream widget appearance.
Malformed top-level containers fail before either panel or theme settings are changed.

Every scalar colour field in `Tokens` is supported:

`window`, `ribbon`, `ribbon_border`, `text`, `text_dim`, `text_disabled`, `accent`, `accent_dark`,
`accent_soft`, `hover`, `pressed`, `separator`, `grid_bg`, `desk`, `gridline`, `header_bg`,
`header_text`, `header_line`, `header_sel_bg`, `header_sel_text`, `header_all_bg`, `sel_fill`,
`sel_border`, `input_bg`, `input_border`, `tab_bar`, `tab_active`, `status_bar`, `cell_text`,
`menu_bg`, `shadow`, `danger`, `notice_warn_bg`, `notice_warn_border`, `notice_info_bg`,
`notice_info_border`.

`dark` is a boolean selector, not a colour token; it is reported as unknown. Use the ordinary
`view.theme {mode:"light"|"dark"|"system"}` command to choose the appearance.

## Ordinary GridCraft control methods

All existing methods remain reachable; see [the control protocol](../../docs/control-protocol.md).

| Method | Result / purpose |
|---|---|
| `engine.execute`, `command`, `ui.menu.invoke` | Run a command; `{command or id,params?}` |
| `engine.commands` | Command descriptors; optional `search` |
| `engine.journal` | Recorded command array |
| `document.inspect`, `sheet.read`, `cell.get`, `selection.stats` | Existing engine state/results |
| `ui.inspect`, `ui.ribbon`, `ui.set` | UI state and existing UI settings |
| `ui.dialog`, `ui.dialog.set`, `ui.dialog.confirm`, `ui.dialog.cancel`, `ui.message.dismiss` | Existing dialogs and message handling |
| `ui.edit.begin`, `ui.edit.text`, `ui.edit.commit`, `ui.edit.cancel` | Existing cell-edit path |
| `ui.click`, `ui.move`, `ui.drag`, `ui.key`, `ui.text`, `ui.cell.click`, `ui.cell.drag` | Queue synthetic input |
| `ui.screenshot` | Presented PNG as base64; browser callers omit native `path` |
| `ui.resize`, `ui.focus`, `app.quit` | Existing viewport requests; the embedding host owns guest lifetime and browser sizing |
| `app.open`, `app.save` | Existing native-path commands; browser hosts should use byte methods |
| Any existing engine command id | Direct control method shorthand |

Each uses the success/error envelope above. Commands with required params keep their upstream
behaviour; host APIs do not add interactive dialogs except the existing unsaved-changes path.

## Branches, tests and upstream pulls

`main` mirrors upstream at `68e58a2eae46`; only `c0/main` receives commits. Never push from this
lane. [PATCH-DEBT.md](PATCH-DEBT.md) enumerates every modified upstream file and the measured
added-line ratchet. New host code is isolated in new files; no spreadsheet parity claim changes.

Run heavy commands with `smoac-slot run heavy 2 3600 -- env CARGO_BUILD_JOBS=2` (fallback to
`smoac-slot run gate 3 3600` only if heavy refuses admission). At most two Cargo jobs run at once.

```sh
cargo test -p gridcraft-ui-egui --test c0_host_contract --test c0_chrome --test c0_theme --test c0_control_passes --test c0_layout --test c0_export --test c0_render
cargo test -p gridcraft-web --features page-control
cargo check --target wasm32-unknown-unknown -p gridcraft-web --features page-control
cargo clippy -p gridcraft-ui-egui -p gridcraft-web --all-targets --features page-control -- -D warnings
cargo xtask ci
```

The web feature's parser and pass policy compile and run in native tests (K-41); its browser half
also compiles in the wasm check and page build. Rendered native tests cover About and Agent
Control; lifecycle tests click the actual upstream Save Changes buttons. Byte tests use generated
workbooks, never vendor fixtures. [LANE-REPORT.md](LANE-REPORT.md) records final evidence, artifact
sizes, host load and assumptions.
